# 隔離環境での限定的な互換性検証

`php-safe-migrate-verify`は、明示的に指定したPHPの旧イメージと新イメージをローカルDockerで実行し、PHP拡張、任意のPHPテストファイル、オプションのComposerプラットフォーム要件を確認します。**移行の安全性や本番投入を承認する機能ではありません。** 結果は常に`deployment_ready: false`、終了コードは未確認事項を示す`2`です。

## 準備と実行

- 信頼できるDockerホストで実行してください。コンテナ隔離にも残余リスクがあります。
- 本番秘密情報を含まない、使い捨てのプロジェクトコピーを使用してください。対象コードはホストでは実行しません。
- 使うPHPイメージを事前に取得・確認してください。ツールは実行時にイメージをpullせず、ローカルのimage IDを記録します。
- `--probe`には、プロジェクト内の相対パスで、旧版と新版の両方で実行するPHPテストファイルを指定します。結果の標準出力・標準エラーは平文のログに残さず、ハッシュとバイト数だけを記録します。

```sh
docker pull php:8.3.36-cli
docker pull php:8.4.27-cli
php-safe-migrate-verify examples/verification-fixture \
  --old-image php:8.3.36-cli \
  --new-image php:8.4.27-cli \
  --probe probe.php
```

別のDocker contextを使う場合は`--docker-context colima`のように指定します。`version-probe.php`を選ぶとPHP版の差が出るため、出力不一致が`blocked`になることを確認できます。

Composerを確認する場合は、信頼できる入手元から確認したローカルのComposer PHARを`--composer-phar /path/to/composer.phar`で指定します。対象プロジェクトには`composer.lock`が必要です。`check-platform-reqs --lock --no-dev`を、ネットワークなし・プラグインなし・スクリプトなしで実行します。**これはロック済み依存関係のプラットフォーム要件の検査であり、依存関係の再解決、ロックファイルの鮮度、PHP拡張の振る舞いは保証しません。** PHARはプロジェクトと別の読み取り専用マウントに置きます。

コンテナはネットワークなし、読み取り専用のプロジェクトマウント、権限削除、非rootユーザー、プロセス・メモリ・CPU制限で実行します。対象のDockerfileやComposeファイルをビルド・起動することはありません。使うイメージの内容自体が信頼できるかは利用者が確認する必要があります。

## この版では確認できないこと

- アプリケーション全体のテスト、HTTP API、外部サービス、DBスキーマ・データの一致
- Composerの依存解決と`composer.lock`の鮮度、配備済みイメージの真正性
- バックアップの復元、ステージング、段階的切替、ロールバック

これらはレポートの`blockers`に残り、結果を「安全」と判定しません。本番環境の認証情報、DB、デプロイ先には接続せず、本番変更を実行するコマンドもありません。
