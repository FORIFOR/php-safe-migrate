# URLから始めるPHP更新の評価

サイトのURLしか分からない担当者でも、PHP更新の確認を始められます。ただし、URLから見える情報と、実際に配備されたPHPやアプリケーションの互換性は別の証拠です。**PHP Safe Migrateは管理するサイトのURLから公開情報を簡易診断できます。** リポジトリ診断とは別の入口です。

## URL簡易診断を実行する

```sh
php-safe-migrate-url https://example.com/ --i-control-domain --refresh > url-assessment.json
```

`--i-control-domain`で管理権限を明示しない限り通信しません。HTTPSのトップページだけを取得し、リダイレクト先は追跡せず、通信は1回、本文は最大64KiBまで読みます。ユーザー名・パスワード、パス、クエリ、非標準ポート、非公開IPを含むDNS応答は拒否します。結果に生のHTMLや全ヘッダーは保存せず、認識したPHP版の手掛かりだけを記録します。手掛かりがなくても診断失敗ではなく`unknown`、複数版が見えた場合は`conflicting`です。PHP以外の`generator`はPHP版として扱いません。

この確認は公開情報に限られます。**表示版だけで脆弱性を確定しません**。`upstream_support_status`はPHP公式のサポート期限との比較であり、ベンダーのバックポートや実際の配備状態を含みません。常に`deployment_ready: false`です。

## 入口と移行判断をつなぐ

| 段階 | 確認できること | 残る確認事項 |
| --- | --- | --- |
| 自社サイトの外部確認 | 公開された`X-Powered-By`/`Server`ヘッダーやHTMLの手掛かり。版が表示されない場合もある | 稼働中のPHP版、ベンダー修正の適用状況、Composer依存関係、アプリの動作 |
| PHP Safe Migrateの静的診断 | Docker/ComposeとComposerに**宣言された**PHP版・制約、収録済みCVEとの一致、移行先候補 | 実際の配備内容、全CVE、実行時の互換性とデータ保全 |
| 隔離検証 | 指定した旧・新PHPイメージでの拡張、PHPテスト、条件付きのComposerプラットフォーム要件 | HTTP/API、DB、復元、切替と切戻し |
| 企業の受入判定 | [本番移行前の必須ゲート](PRODUCTION_ASSURANCE.ja.md)を対象環境の証拠で満たす | 人の明示的な承認と、個別の責任・保証範囲の合意 |

[AGIラボの簡易PHP診断](https://agi-labo.com/tools/php-diagnosis)は、URLを入力して外部から見えるヘッダーやHTMLを調べる入口の一例です（2026年10月24日に公開ページを確認）。同ページは、バージョン番号を変えずに修正を適用するレンタルサーバーがあることも説明しています。この種の結果を「安全」や「脆弱」と確定する証拠にはしません。PHP Safe Migrateは、外部サービスの診断結果を取り込んだり、そのサイトへ通信したりしません。

## サイト担当者が次に集める情報

1. **自社が管理するサイト**のURLと、外部確認で得られた手掛かりを記録します。版が見えなければ「不明」と記録します。
2. 制作会社・運用会社に、稼働中のPHP版、配備イメージのdigestまたはホスティング事業者の管理画面、ベンダーの修正情報を確認します。公開ヘッダーの値だけで判断しません。
3. 機密情報を除いたリポジトリまたは設定ファイルを入手し、[READMEの手順](../README.md#自社プロジェクトを診断する)で静的診断します。対象コードは実行されません。
4. [企業向け評価ガイド](ENTERPRISE_EVALUATION.ja.md)に従って、隔離環境での互換性・データ・復旧の確認を計画します。

制作会社に依頼する場合は、次の文面をそのまま使えます。

> 当社サイトで稼働しているPHPの版、ホスティング事業者による修正適用状況、関連するComposer依存関係をご確認ください。PHP更新が必要な場合は、非本番環境での動作確認、データ整合性、バックアップからの復元、切戻しの計画と見積もりもお願いします。公開ヘッダーだけでは判断できないため、実際の配備情報をご提示ください。

現行のCLIは管理権限の自己申告を要求します。公開Webサービスとして任意のURLを受け付けるには、ドメインの所有確認、利用者単位のレート制限、運用ログ・プライバシー設計を追加する必要があります。CDNやベンダー修正がある場合、表示版だけから修正適用を判定しません。
