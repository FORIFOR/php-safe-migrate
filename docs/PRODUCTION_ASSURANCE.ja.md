# 本番移行の安全性をどう保証するか

企業が必要とするのは、対象環境を特定し、検証結果に基づいて責任を持てる保証です。PHP Safe MigrateのOSSライセンスや診断結果だけでは、個別の本番システムの安全性を保証できません。現行版は本番投入の判定を常に拒否します（`deployment_ready: false`）。

## 保証の単位

保証を提示する場合は、少なくとも次を記録した**個別の移行計画**を対象にします。

- アプリケーションのコミット、Composerロックファイル、旧・新PHPイメージのdigest、拡張とOS構成
- 対象サービス、API、バッチ、DB、外部連携、許容停止時間、性能の許容差
- 検証用データの作成方法と、本番データを含めないための手順
- 検証日時、実行者、使用したツールの版、証拠の保存先と保存期間
- 承認者、切替手順、停止条件、復旧責任者、連絡経路

構成が変わったら、該当する証拠は失効し、再検証が必要です。「全てのPHPアプリで安全」「障害ゼロ」といった無条件の主張はしません。

## 本番切替前の必須ゲート

| ゲート | 必要な証拠 | 不合格・不明な場合 |
| --- | --- | --- |
| セキュリティ | 実際に配備するイメージdigest、PHP/OSベンダーの修正情報、依存関係の確認 | 切替停止 |
| 互換性 | 旧・新環境での既存テスト、拡張、Composer要件、主要バッチの結果 | 切替停止 |
| 外部動作 | 代表的なHTTP/API応答、認証、権限、エラー処理、外部連携の比較。許容差は事前承認 | 切替停止 |
| データ | DBスキーマ、件数、整合性制約、重要データのチェックサム。差分の説明と承認 | 切替停止 |
| 復旧 | 取得したバックアップから隔離環境への復元成功、復旧時間の計測 | 切替停止 |
| 段階的切替 | ステージングと限定トラフィックでのヘルスチェック、監視、停止基準 | 切替停止 |
| ロールバック | 切戻し手順の実地演習と、切戻し後の動作・データ確認 | 切替停止 |
| 人の承認 | 対象、証拠、残存リスク、実行時刻を示した変更申請への明示的な承認 | 切替停止 |

単にテストが通っただけでは合格にしません。未実施、対象外、結果不明、証拠の期限切れはすべて未合格です。データの不可逆な変更がある場合は、旧版への単純な切戻しが成立するかを個別に確認します。

## 現行版で提供できる証拠

静的診断は宣言されたPHP版と収録済みCVE等を照合します。[隔離検証](ISOLATED_VERIFICATION.ja.md)は、指定したローカルイメージで拡張、PHPテスト、条件付きのComposerプラットフォーム要件を確認します。どちらも上表の全ゲートを満たせず、**本番切替の許可や安全保証を発行しません**。現在の試験結果は[検証記録](VALIDATION.md)にあります。

将来、全ゲートの証拠収集・差分評価・監査記録を実装しても、ツールの判定だけで本番変更は実行しません。企業固有の保証範囲、責任分担、障害時対応、賠償条件やSLAは、対象システムと検証結果を確認したうえで別途契約として定める必要があります。OSSのApache-2.0ライセンスは、そのような個別保証を付与するものではありません。

評価を始める場合は[企業向け評価ガイド](ENTERPRISE_EVALUATION.ja.md)に従い、機密情報を除いた結果と必要な保証範囲を[Discussions](https://github.com/FORIFOR/php-safe-migrate/discussions)で相談してください。本番環境へのアクセス情報や個人情報は公開しないでください。
